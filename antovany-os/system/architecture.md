# Antovany OS Architecture

## Purpose

Antovany OS is a personal intelligence architecture, not merely a file hierarchy. Its purpose is to increase decision quality, preserve institutional memory across AI systems, and convert experience into reusable strategic assets.

## Layer model

### 1. Evidence Layer
Canonical, original, or source-grade material: contracts, correspondence, financial records, research, transcripts, analytics exports, source decks, and raw notes.

**Preferred systems:** Google Drive / Docs, email, connected source systems.

### 2. Workspace Layer
Active projects, tasks, dashboards, meeting notes, PARA organization, status tracking, and operational context.

**Preferred system:** Notion.

### 3. Intelligence Layer
Frameworks, synthesis, assumptions, decision logs, knowledge objects, prompt/skill logic, schemas, and reusable analytical methods.

**Preferred systems:** Notion + GitHub.

### 4. Authority Layer
Public-facing thought leadership, Decision Briefs, cases, portfolio proof, and searchable reputation assets.

**Preferred system:** antovany.com / CEO Decision Lab.

### 5. Interaction Layer
AI-assisted simulation, case solving, Q&A, and personalized reasoning experiences.

**Preferred system:** Brainy Lab and compatible AI assistants.

## PARA alignment

- **Projects:** time-bound outcomes with a clear definition of done.
- **Areas:** ongoing responsibilities and standards to maintain.
- **Resources:** reusable knowledge that may support future decisions.
- **Archives:** inactive or completed material kept for reference.

GitHub should primarily host reusable Resources and selected system-level Areas, not private project evidence.

## Source-of-truth rule

Every important object should have one canonical source. Other systems may contain:

- links,
- summaries,
- derived analysis,
- machine-readable metadata,
- redacted public versions.

Do not maintain multiple uncontrolled canonical copies.

## Knowledge object design

A reusable knowledge object should ideally contain:

- title
- type
- domain
- summary
- source pointers
- evidence status
- confidence
- assumptions
- implications
- decision relevance
- privacy classification
- as-of date
- review date
- related entities/projects

## Decision loop

1. Frame the decision.
2. Separate facts from assumptions.
3. Generate alternatives.
4. Identify second-order effects.
5. Define reversible vs irreversible components.
6. Select leading indicators and guardrails.
7. Decide with an explicit rationale.
8. Record what would invalidate the decision.
9. Review outcomes and update the knowledge base.

## Design objective

The system should make future Antovany and future AI collaborators smarter than the current version by reducing rediscovery, preserving reasoning artifacts, and making assumptions auditable.
